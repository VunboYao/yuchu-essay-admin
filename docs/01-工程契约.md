## 定位

- **业务范围** = 现有 Vue Admin：登录 + 11 个业务页，对接 `course_server` `/admin/api/v1`。
- **工程质量** = 中型团队 React SPA 后台标准，不因业务体量小而降级。
- **对等范围**（已拍板）：路由 path、菜单分组、API 路径与字段、业务规则。
- **不对等**：UX 与实现按 React 企业级做——不照搬全局 Loading、拦截器 toast/跳转、页内 `load()` + `ref`。

不是 Demo，不是「先跑起来再补」。验收通过「能点通」但 `pnpm verify` 红灯 = 未完成。

## 禁止（比范围更硬）

| 禁止 | 正确做法 |
|------|----------|
| 为学 API 单独做 throwaway 演示页 | Query 的第一次使用必须是真实业务页（标签 CRUD） |
| `any` / `@ts-ignore` / 无说明的 `eslint-disable` | 补类型；禁用必须写清原因与拆除条件 |
| `useEffect` 拉列表，或手写第二份 list state | TanStack Query；写成功后 `invalidateQueries` |
| Axios 拦截器里 `message` + `navigate` | HTTP 只抛 `ApiError`；401 调 `authStore.getState().clear()`；UI 在 Query / `AuthGate` |
| 迁 Vue 的全局 Loading 引用计数 | 页级 `isPending` / Dialog 确认中禁用 |
| Zustand 存服务端列表/详情/统计 | Zustand **仅** auth |
| Ant Design Form 与 RHF 两套状态混用 | 写操作一律 zod + RHF；Ant 控件用 `Controller` |
| 测试留到最后当加分项 | 信任边界测试随 Step 交付（见下文） |
| 预防性 `memo` / `useMemo` / `useCallback` | 默认不写；有卡顿证据再加 |
| 第一页抽万能 `useCrud` | Rule of Three：第二份相同 CRUD 出现后再抽薄层 |
| 11 页复制 200 行同一骨架 | 同上；禁止「能跑就粘贴」 |
| React Router `loader` 拉业务数据 | Router 只负责路由；数据全走 Query（禁止双缓存） |
| 留下 Vite 计数器 / Hello 占位当验收产物 | 路由模块从第一天就是真实 feature 文件 |
| 改 `Admin/`（Vue） | 只读对照 |

## 目录（锁定）

```text
src/
  app/                      # 应用壳，不放业务
    providers/              # QueryClient、Antd ConfigProvider、ErrorBoundary
    router/                 # createBrowserRouter、AuthGate
    layouts/                # AdminLayout
  shared/
    api/                    # http 客户端、ApiError、token 注入
    query/                  # QueryClient 默认配置（staleTime 等）
    config/                 # env 用 zod parse
    ui/                     # AppFormDialog、QueryState、PageHeader
    styles/                 # design token / CSS 变量
    types/                  # 跨 feature 的 API DTO（从 Vue types 迁并收紧）
  features/
    <域>/
      api.ts
      queries.ts            # queryKeys + queryOptions()
      schemas.ts            # zod
      pages/
      components/           # 仅本域用
      __tests__/
```

Feature 域与路由对应：`auth` `dashboard` `article` `essay` `download` `taxonomy` `tag` `home-block` `ad-slot` `official-account` `feedback` `operation-log`。

跨 feature 只允许：

- 依赖 `shared/`
- 明确的 `invalidateQueries(otherKeys.all)`（例如文章页内联建标签 → `tagKeys.all`）
- 禁止 `features/a` 直接 import `features/b` 的页面或内部组件

## 技术用法（对标企业，不因项目小降级）

### TypeScript

- `strict` + `noUncheckedIndexedAccess`
- 组件显式 `type Props = { ... }`，不用 `React.FC`
- `import.meta.env` 经 `shared/config` 的 zod schema 解析后再用，禁止满项目散落 `import.meta.env.VITE_*`

### HTTP

```ts
class ApiError extends Error {
  status?: number
  code?: number
  isUnauthorized: boolean
}
```

- 响应 `code === 0` 解包 `data`；否则 `throw new ApiError(...)`
- token 从 `authStore.getState()` 读，**不从 React / hook 读**
- 401：`clear()` 登录态；登录接口本身不当成「过期跳转」
- 拦截器不调 UI 库、不 `navigate`

### TanStack Query

- 每域 `queryKeys` 工厂 + `queryOptions()`，禁止页面魔法串
- `queryKey` 必须包含影响结果的筛选 / 分页参数
- `staleTime` 等默认值写在 `shared/query` 的 QueryClient，不在每页各写一套
- 区分 `isPending`（首次）与 `isFetching`（后台刷新）
- 写成功：`invalidateQueries` 对应 key 前缀，不要再 `setList`

### 路由与鉴权

- `createBrowserRouter` + 布局路由 + `lazy` + `Suspense`
- **AuthGate 组件守卫**（无 token → `/login?redirect=`；已登录访登录页 → `/dashboard`）
- 不要仿 Vue `beforeEach` 在路由表里堆副作用
- token key 仍为 `admin_token`（可与 Vue 共用后端会话）

### 表单

- 所有写操作：zod schema + RHF + `@hookform/resolvers/zod`
- Ant Design 受控控件必须 `Controller`，不要硬套 `register`
- 校验失败错误落到对应 Form.Item；提交中禁用确认按钮
- Dialog：禁点遮罩关闭（对齐 Vue 产品行为）

### 状态分层

| 数据 | 放哪 |
|------|------|
| 登录 token / 管理员信息 | Zustand `persist`（仅 `features/auth`） |
| 列表 / 详情 / 统计 | TanStack Query |
| 弹窗开关、表格选中、本地草稿 | 组件 `useState` |
| 派生过滤 / 展示 | 直接计算，禁止 Effect 同步到另一份 state |

### 测试（随 Step 交付，不是加分项）

栈：Vitest + Testing Library + jsdom。测**行为**，不测实现细节。

| 时机 | 必测 |
|------|------|
| Step 1 | 工程可跑：至少 1 个 smoke（如 env parse 或 `ApiError` 占位前的 config） |
| Step 3 | 无 token 访问受保护路由 → 登录页（可测 AuthGate） |
| Step 4 | 解包 `code === 0`；`code !== 0` 抛 `ApiError`；401 清态；登录接口 401 不按过期跳转 |
| Step 6+ 每个写表单 | 对应 zod schema（合法通过 / 非法拒绝） |
| Step 6 | `queryKey` 含筛选/分页（断言 key 工厂输出，不测网络） |

不追求覆盖率数字。`pnpm verify` 红 = 该 Step 未验收。

### 工程脚本

```text
pnpm verify  =  lint && type-check && test
```

lint 用 **Oxlint**（替代 ESLint + Prettier）。Vitest 暂缓接入前，`verify` 暂为 `lint && type-check`。

Step 1 就必须绿。本仓是 monorepo，**不加仓库根 husky**（避免绑死整个 course 仓）。

开发端口 **5174**；proxy `/admin/api` → `:8080`。

### 样式

- 默认 CSS Modules + `shared/styles` 的 CSS 变量 token
- 不上 Tailwind；不上 Storybook / Redux / Next

## 「像有 3 年 React」的审查条

每步验收，作者应能口头答出：

1. 这段 state 为什么在 Query / Zustand / 组件本地，而不是另外两处？
2. 这个 `useEffect` 若删掉，产品会坏什么？（答不出就删）
3. 首次加载、空列表、请求失败、后台刷新，用户分别看到什么？
4. 这个自定义 hook 包的是非平凡逻辑，还是 one-liner 套壳？
5. Dialog / 表单的 label、确认中禁用、焦点，有没有交给 Ant Design 而不是自造残缺模态？

Reviewer 按 [`.cursor/rules/admin-react-code-review.mdc`](../../.cursor/rules/admin-react-code-review.mdc) 执行；质量条款以本文为准。

## 与 Vue 对照：禁止照搬清单

读 Vue 时只记「做什么」，遇到下列实现直接跳过：

| Vue Admin 现状 | React 禁止照搬的原因 |
|----------------|----------------------|
| axios 解包标 `any` | 类型在信任边界必须闭合 |
| 拦截器 `ElMessage` + `router.replace` | HTTP 与 UI 耦合，测试/复用都痛 |
| `globalLoading` 引用计数 | 掩盖每页真实加载态；与 Query 重复 |
| 页内 `load()` + `loading ref` + `list ref` | 服务端状态的过时模式 |
| Element `FormRules` 手写 | 用 zod 做单一校验源 |
| Pinia 手写 `localStorage.setItem` | Zustand `persist` |
| `router.beforeEach` 读 localStorage | `AuthGate` + store 选择器 |

字段名、status 枚举、OSS `subdir`、删除二次确认等**业务规则**仍须一致。
