## 1. 一个页面这么多 import，会不会太复杂？

**不会。复杂的是页面职责，不是 import 行数。**

React 没有 Vue SFC 的 `<script setup>` 自动收集，每个符号都必须显式 import。15 行引入 ≈ Vue 页里 `antd` + 自己的 composable + 类型，只是摊开写了。

更准确的分层已经做了：

- UI 壳：`PageHeader` / `AppFormDialog` / `QueryState`（barrel `@/shared/ui`）
- 表单字段：`TagForm` 已拆走
- HTTP：`../api`；缓存身份：`../queries`；校验：`../schemas`

剩下的 `useQuery` / 三个 `useMutation` / `columns` / 筛选项，就是「这一页的编排」。Vue Admin 的标签页同样是一张表 + 弹窗 + 筛选，只是 import 藏在 SFC 里更不显眼。

不必为了缩短 import 再抽一层 `useTagPage`。01 工程契约明确禁止第一页抽万能 `useCrud`。

小瑕疵（不是复杂度）：`STATUS_OPTIONS` 与 `statusLabel` 从同一模块拆了两次，合并成一行即可。**现在不用改。**

## 2. 后续会不会继续拆组件？`columns` 会抽走吗？

**现阶段不会为拆而拆。** Step 6 文档写死了：

- `columns` 可以写在组件里；禁止预防性 `useMemo`
- 表单字段可以抽（已经抽了 `TagForm`）
- CRUD 流程不要抽；禁止 `useCrud` / `useListPage`

抽离门槛是 **Rule of Three**：第二份相同结构出现后再抽薄层。计划里这是 **Step 7 教材分类**——若与 tag 页大段复制，才允许抽 list hook，仍不是万能 CRUD。

`columns` 抽成 `TagTable` 目前没收益：它闭包了 `openEdit` / `handleToggleStatus` / `handleDelete` / `actionsLocked`，抽出去还要把这些当 props 传回来，文件变多、心智不变少。等第三张结构几乎一样的表再考虑「columns 工厂」或共享操作列。

```text
现在 Step 6
  TagPage → TagForm / QueryState / AppFormDialog

Step 7 之后才考虑
  薄层 list hook
  重复 columns 再抽
```

## 3. TanStack Query

### 3.1 `query-client.ts`：项目级默认值 — 对

唯一 `QueryClient`，经 `QueryClientProvider` 注入。当前默认：

- `staleTime: 30_000`：30 秒内 fresh，切菜单不重打；真要最新靠写后 invalidate
- `retry: 1`（query）/ `0`（mutation）：写操作不要自动重试
- `refetchOnWindowFocus: false`

页面可以覆盖（例如 `placeholderData`），但不要在每个 `useQuery` 再抄一遍 `staleTime`。

### 3.2 `queries.ts`：key + queryFn 工厂 — 对

避免页面手写 `['tags']`。两层地址用途不同：

| 工厂 | key | 谁用 |
|---|---|---|
| `tagKeys.list(query)` | `['tags','list', query]` | `useQuery` 订阅「这一页」 |
| `tagKeys.lists()` | `['tags','list']` | `invalidateQueries` 前缀匹配所有列表 |
| `tagKeys.all` | `['tags']` | 将来有 detail 时，打全部 tag 查询 |

`tagQueries` **只放读**。create / update / delete 不进这个文件。

### 3.3 `useQueryClient` + `invalidateQueries` — 说错了：不是销毁缓存

`useQueryClient()` 不是调业务 API，是从 Context 取出那个单例客户端。

`invalidateQueries({ queryKey: tagKeys.lists() })` 做的是：

1. 把所有以 `['tags','list']` 开头的查询标成 **stale**
2. **当前有组件订阅的**，立刻 refetch
3. 没人订阅的，下次再被 `useQuery` 时才重拉

旧 `data` 一直留着，直到新响应覆盖。所以表格不会先变空白。这和「销毁」相反。

真删除缓存的是 `removeQueries`；回到初始态是 `resetQueries`。本页都没用。

```text
mutation 成功
  → invalidate（标 stale + 活跃的重拉）
  → 同一条 useQuery 拿到服务端权威列表
  → 没有第二份 setList
```

### 3.4 列表 `useQuery` — 对，补一句 v5 坑

```ts
useQuery({
  ...tagQueries.list(query),         // queryKey + queryFn
  placeholderData: keepPreviousData, // 翻页时把上一页 data 借给新 key
})
```

`query` 变 → key 变 → 当成另一份查询。不要 `refetch(newParams)` 传筛选。

v5 关键：有 `keepPreviousData` 时，新 key **仍是 `isPending`**，只是 `isPlaceholderData === true` 且 `data` 是上一页。所以整页骨架必须写成 `isPending && !isPlaceholderData`。

### 3.5 三个 `useMutation` — 大体对，用词收紧

它们不是「声明三个操作方法」，而是 **注册三种写操作的状态机**。`mutationFn` 才是真正打接口的函数；hook 返回 `mutate` / `mutateAsync` 去触发。

`mutate(variables)` 的 `variables` **就是 `mutationFn` 的入参**：

- `createTag(input)` → `mutateAsync(input)`
- `updateTag({ id, input })` → `mutate({ id, input })`
- `deleteTag(id)` → `mutateAsync(id)`

hook 级常用配置（本页只用了前两个）：

- `mutationFn`（必填）
- `onSuccess` / `onError` / `onSettled`：每次调用都跑（页面级同步缓存放这里）
- `onMutate`：乐观更新 + 返回回滚快照（本页不用）
- `retry`：走项目默认 0
- `mutationKey` / `scope`：按 key 过滤或串行排队（本页不用）
- `throwOnError`：把错误丢给 Error Boundary

`mutate` vs `mutateAsync`：

| | `mutate` | `mutateAsync` |
|---|---|---|
| 返回值 | `void` | `Promise`，可 `await` |
| 失败 | 进 `onError`，不抛到调用方（除非 throwOnError） | reject，可 `try/catch` |
| 本页 | 行内切换状态（只要 toast） | 弹窗提交 / 删除（成功才关窗、成功 toast） |

不要写 `await xxx.mutate(...)`。

### 3.6 `mutate` 第二个参数 — 是「这一次」的回调，不是完整配置

```ts
updateMutation.mutate(variables, {
  onError: (error) => { ... },
})
```

per-call 只支持：`onSuccess` / `onError` / `onSettled`（没有 `onMutate`、没有 `retry`）。`mutateAsync(vars, 同样这三个)` 同理。

分工约定（08 文档）：

- **hook 级 `onSuccess`**：失效缓存（每次成功都要做）
- **per-call `onError` / 外层 try/catch**：这一次的 toast / 关窗

并发多次 `mutate` 时，**只有最后一次** 的 per-call 回调会触发。所以缓存同步不要只写在第二个参数里。

### 3.7 `queryStatus` 那一堆：两根轴 + 产品四态

Query v5 是二维状态，不要当成一个 loading 布尔：

```text
status      = 有没有一份「真实成功结果」   pending | error | success
fetchStatus = queryFn 现在在干什么         fetching | paused | idle
```

`QueryState` 要的是产品四态：`pending | error | empty | success`。页面把 Query 的二维状态 **派生** 成这四个，默认先当 `success`，再按优先级覆盖：

```text
1. isPending && !isPlaceholderData     → 整页骨架（首次、无缓存）
2. !data && isError                    → 整页错误（首次就失败）
3. data.list.length === 0              → 空态（搜不到也算）
4. 其余                                → success，渲染 Table
```

场景对照：

```text
首次进页，无缓存
  isPending=true, isPlaceholderData=false, data=undefined
  → pending（Skeleton）

翻页（keepPreviousData）
  新 key 仍 isPending=true，但 isPlaceholderData=true，data=上一页
  → 不能判 pending，否则占位白做；走 success，Table overlay 转圈

已成功，后台刷新（stale 后 refetch / invalidate）
  isPending=false, isFetching=true, data 还在
  → 仍 success；Table loading={isFetching}

后台刷新失败
  isError=true，但 data 还在，isRefetchError=true
  → 仍 success + 顶部 Alert（showFetchError）
  → 若写成 isError 就整页 error，表格会被卸掉

成功但 list=[]
  → empty；data 为 undefined 时 ?. 不会误判
```

`useQuery` 还常用、本页没用或只间接用的：

| 字段 | 含义 | 本页 |
|---|---|---|
| `isFetching` | 任何在飞（含后台刷新） | Table overlay |
| `isRefetchError` | 刷新失败且旧 data 还在 | Alert |
| `isSuccess` / `isLoading` / `isRefetching` | 派生布尔 | 未直接用 |
| `data` / `error` / `refetch()` | 结果与手动重拉 | 渲染 / 文案；筛选靠改 `query` 不靠 refetch |

**`useMutation` 没有这套二维机**，也没有 `isPlaceholderData` / `isFetching` / `isRefetchError`。它是一维：

```text
idle → pending → success | error
```

本页实际读的 mutation 状态：

| 字段 | 用途 |
|---|---|
| `isPending` | `actionsLocked`、Dialog `confirmLoading` |
| `mutate` / `mutateAsync` | 触发 |
| hook `onSuccess` | invalidate |

还有但本页没用：`isIdle` / `isSuccess` / `isError` / `error` / `data` / `variables` / `reset()`（清掉这次 mutation 的 data/error，和 RHF 的 `reset` 不是一回事）/ `failureCount`。

## 4. RHF 的 `reset`

`defaultValues` **只在 `useForm` 首次创建时生效**。本页创建/编辑共用同一份 form + 同一个 Dialog，不卸载重挂，所以必须命令式灌值：

```ts
openCreate → reset(createDefaults)                  // 清空成「新建」
openEdit   → reset({ name, sortOrder, status })     // 灌入该行
```

类比 Vue：不是改 `reactive(form)` 的初始值，而是 `Object.assign` / 再跑一遍初始化。Ant Design Form 的 `form.setFieldsValue` + `form.resetFields` 也是同一类命令式 API。

常用选项（本页都走默认）：`keepDefaultValues`、`keepErrors`、`keepDirty`、`keepTouched`。成功提交后本页靠关窗 + 下次 `openCreate` 再 `reset`，没有在 mutation `onSuccess` 里 `reset()`（08 学习切片里创建表单那样写过）。

`useMutation` 也有 `reset`，那是清 mutation 状态，别和 RHF 搞混。
