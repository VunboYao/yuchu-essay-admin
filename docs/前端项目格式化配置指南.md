# 前端项目格式化配置指南

这套配置适用于使用 Cursor / VS Code 开发的 React、Vue 和 TypeScript 项目。目标是让职责保持单一：

- Prettier 负责代码排版。
- ESLint / Oxlint 负责代码质量检查。
- EditorConfig 负责跨编辑器的基础文本格式。
- 每种语言只指定一个保存时格式化器，避免 Prettier 与 ESLint 同时改写文件。

## 一、准备 Prettier 插件

在 Cursor 中安装：

```text
Prettier - Code formatter
扩展 ID：esbenp.prettier-vscode
```

只在编辑器中保存时格式化，可以直接使用插件内置的 Prettier，不需要执行 `pnpm add prettier`。

只有以下场景才建议把 Prettier 安装为项目依赖：

- CI 需要执行格式检查。
- 团队要求锁定统一的 Prettier 版本。
- `package.json` 需要提供 `format` / `format:check` 命令。

## 二、处理 Cursor 全局 ESLint 配置冲突

Cursor 的配置优先级是：

```text
工作区配置 > 用户全局配置 > 编辑器默认配置
```

如果用户全局配置中存在以下设置：

```json
{
  "prettier.enable": false,
  "eslint.format.enable": true,
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": {
    "source.fixAll": "always"
  }
}
```

直接启用 Prettier 可能出现两个问题：

1. `prettier.enable: false` 导致插件不运行。
2. ESLint 的格式化或 `source.fixAll` 与 Prettier 同时改写文件，出现反复格式化、内容抖动，严重时表现为保存卡顿。

解决原则：

1. 在项目的工作区配置中重新启用 Prettier。
2. 为目标语言明确指定 Prettier 是唯一的 `defaultFormatter`。
3. 禁止这些语言在保存时执行 ESLint 的 `fixAll`。
4. ESLint / Oxlint 改为通过 `lint`、`verify` 等项目命令检查。

## 三、React / TypeScript 项目的工作区配置

在项目的 `.vscode/settings.json` 中写入：

```json
{
  "prettier.enable": true,
  "prettier.requireConfig": true,
  "editor.formatOnSave": true,
  "[typescript]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll": "never",
      "source.fixAll.eslint": "never"
    }
  },
  "[typescriptreact]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll": "never",
      "source.fixAll.eslint": "never"
    }
  }
}
```

如果项目使用 `.js` / `.jsx`，再补充：

```json
{
  "[javascript]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll": "never",
      "source.fixAll.eslint": "never"
    }
  },
  "[javascriptreact]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll": "never",
      "source.fixAll.eslint": "never"
    }
  }
}
```

`prettier.requireConfig: true` 表示只有项目中存在 Prettier 配置文件时才格式化，避免插件无意中接管其他项目。

### Monorepo 注意

单项目中，`.vscode/settings.json` 直接放在项目根目录。

如果 Cursor 打开的是 monorepo 根目录，只有根目录的 `.vscode/settings.json` 会作为工作区配置生效；子项目里的 `.vscode/settings.json` 不会自动生效。此时：

- 工作区配置放到 monorepo 根目录。
- `.prettierrc` 放到需要 Prettier 的子项目中。
- 使用 `prettier.requireConfig: true`，避免没有 Prettier 配置的子项目被接管。

本仓库正是这种结构：

```text
course/
├── .vscode/settings.json
└── Admin-React/
    ├── .editorconfig
    └── .prettierrc
```

## 四、EditorConfig 配置

项目根目录的 `.editorconfig`：

```ini
root = true

[*]
indent_style = space
indent_size = 2
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true

[*.md]
trim_trailing_whitespace = false
```

职责：

- 使用两个空格缩进。
- 统一为 LF 换行符。
- 文件末尾保留换行。
- 清理行尾空格。
- Markdown 允许保留行尾空格，避免破坏依赖两个空格实现的硬换行。

`.editorconfig` 不负责 JSX 属性、数组、对象等语法结构的换行，因此不能替代 Prettier。

## 五、Prettier 配置

项目根目录的 `.prettierrc`：

```json
{
  "semi": false,
  "singleQuote": true,
  "printWidth": 100
}
```

配置含义：

- `semi: false`：不主动添加分号。
- `singleQuote: true`：JavaScript / TypeScript 字符串优先使用单引号。
- `printWidth: 100`：以 100 字符作为自动换行参考宽度，适合现代 React / Vue 项目。

Prettier 会读取 `.editorconfig` 中的部分基础设置，因此不要在两个文件里重复维护缩进和换行符配置。

## 六、Vue 项目如何配置

`.editorconfig` 和 `.prettierrc` 可以与 React 项目完全相同。

区别只在工作区配置：Vue 单文件组件的语言 ID 是 `vue`，需要明确指定 Prettier：

```json
{
  "prettier.enable": true,
  "prettier.requireConfig": true,
  "editor.formatOnSave": true,
  "[vue]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll": "never",
      "source.fixAll.eslint": "never"
    }
  },
  "[typescript]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll": "never",
      "source.fixAll.eslint": "never"
    }
  },
  "[javascript]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.fixAll": "never",
      "source.fixAll.eslint": "never"
    }
  }
}
```

如果 Vue 项目已经使用 ESLint 统一完成格式化，也可以继续只用 ESLint，不必为了统一工具而强行引入 Prettier。真正需要避免的是让 ESLint 和 Prettier 同时处理引号、分号、缩进、换行等相同规则。

## 七、复制到新项目的操作清单

1. 安装并启用 `Prettier - Code formatter` 插件。
2. 复制 `.editorconfig`。
3. 复制 `.prettierrc`。
4. 复制对应技术栈的 `.vscode/settings.json`。
5. 打开一个 `.ts`、`.tsx` 或 `.vue` 文件，执行一次“格式化文档”。
6. 保存文件，确认只触发 Prettier，不再触发 ESLint 格式化。
7. 单独运行项目的 `lint` / `verify` 命令确认代码质量。

如果配置未立即生效，执行：

```text
Command Palette → Developer: Reload Window
```

仍未生效时，依次检查：

- Prettier 插件是否启用。
- 当前文件右下角的语言模式是否正确。
- “Format Document With...”中默认格式化器是否为 Prettier。
- 当前文件向上是否能找到 `.prettierrc`。
- 工作区配置是否覆盖了全局的 `prettier.enable: false`。
